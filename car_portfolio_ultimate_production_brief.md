# CAR-LED CINEMATIC PORTFOLIO — ULTIMATE PRODUCTION BRIEF

**Status:** Final creative + motion + engineering brief
**Primary implementation target:** GPT-5.6 Sol / senior creative developer workflow
**Primary experience:** Desktop-first, cinematic, scroll-led portfolio
**Core visual language:** Cars, mechanical detail, bodywork, engineering surfaces, light, motion, sound
**Copy philosophy:** Minimal text. No generic AI-copy.
**Critical quality bar:** Every transition must feel deliberate, stable, smooth, dimensional, and premium.

---

# 0. READ THIS FIRST

This is a **complete redesign**.

Forget the previous concept involving explorable 3D worlds, stadium environments, horror rooms, garages as full environments, or large scene-based world building.

The new portfolio is built around **vehicles as the primary visual language**.

The car itself is the stage.

The car itself is the transition.

The car itself is the interface.

The car itself carries the personality of each portfolio section.

Backgrounds should support the subject only. They are not the attraction.

The portfolio should feel closer to:

- a premium automotive launch film
- a high-end title sequence
- an F1 broadcast cinematic package
- an automotive commercial
- a luxury product website with film-level motion design

than to a normal personal portfolio.

---

# 1. CORE CONCEPT

Build an extremely polished, minimal-text portfolio where each major section is represented by a distinct vehicle or motorsport visual language.

The site should feel like one continuous cinematic edit controlled by scroll.

The user does not simply scroll through sections.

They move through **shots**.

They move through **mechanical reveals**.

They move through **macro details**.

They move from one vehicle language into another through seamless transitions.

### Primary vehicle mapping

- **Experience → McLaren Senna**
- **Projects → Formula 1**
- **About → Nissan Skyline GT-R R34**
- **Creative / VFX / Writing → secondary automotive/editorial sequences, integrated into the same visual system**

This mapping is not decorative.

Each vehicle should embody the section:

- **Senna:** precision, intensity, professional execution, performance
- **F1:** engineering, systems, iteration, technical projects
- **Skyline:** identity, obsession, personality, roots, taste

# 4. IMAGE QUALITY PIPELINE

The supplied sample images are mostly reference-resolution assets.

They should **not** simply be scaled up in CSS and used as-is.

Before any final visual is placed into production, it must pass through a quality pipeline.

## 4.1 Production image target

For desktop hero visuals, aim for source assets equivalent to:

- minimum practical width: ~2400 px
- preferred hero width: 3200–4096 px where justified
- clean high-frequency detail
- no obvious JPEG damage
- no excessive sharpening halos
- no smudged logos
- no melted panel lines
- no distorted wheels or brake hardware

## 4.2 AI enhancement can be used

AI may be used to:

- upscale
- denoise
- restore detail
- repair compression damage
- create depth maps
- create alpha masks
- extend framing
- create alternative clean compositions
- create missing mechanical angles
- create original close-ups inspired by the sample mood

But enhancement must preserve vehicle identity.

## 4.3 Accuracy QA is mandatory

AI-generated automotive visuals often make subtle mechanical mistakes.

Before using a generated image, verify:

- number and placement of headlights
- grille geometry
- wheel spoke design
- brake caliper placement
- badge placement
- intake shapes
- aero surfaces
- exhaust geometry
- body panel seams
- mirror placement
- door geometry
- engine layout when visible
- cockpit layout for F1

A highly cinematic image with an incorrect car is not acceptable.

## 4.4 Preferred strategy for exact vehicles

For hero shots requiring maximum accuracy, prefer this hierarchy:

1. high-quality licensed / owned photography or 3D render
2. high-quality accurate 3D vehicle model rendered specifically for the site
3. AI-generated original visual with aggressive reference verification
4. AI-enhanced sample only when rights and fidelity are appropriate

AI should support accuracy, not replace visual QA.

# 5. MAKE 2D IMAGES FEEL AS 3D AS POSSIBLE

The site does **not** need full 3D worlds.

However, the vehicles must feel dimensional.

A still car image should never feel like a flat PNG sliding across the page.

Use a layered image-depth system.

## 5.1 Techniques allowed

Use combinations of:

- depth maps
- displacement maps
- perspective transforms
- image segmentation
- foreground / subject / background separation
- depth-aware parallax
- WebGL shaders
- masked lighting passes
- animated reflections
- subtle camera dolly simulation
- focal-plane changes
- controlled perspective scaling
- light sweeps
- lens distortion in transitions
- chromatic separation only where extremely restrained
- image sequences
- rendered turntable frames
- 3D meshes for selected components

## 5.2 2.5D depth stack

For a hero image, separate into layers such as:

1. background
2. rear body surface
3. cabin / glass
4. front body / wheel
5. foreground component
6. light / reflection pass
7. shadow / contact pass
8. optional volumetric layer

Move these at slightly different rates.

The motion should be subtle enough to feel like camera movement rather than a parallax demo.

## 5.3 Use real 3D selectively

Real 3D is encouraged for isolated hero components where it materially improves the illusion.

Examples:

- wheel / tyre
- brake disc
- Senna door
- engine component
- F1 steering wheel
- suspension arm
- turbine / intake detail

Do not recreate giant environments just because Three.js exists.

# 6. MOTION DESIGN NORTH STAR

The entire site should feel like a continuous automotive cinematic.

Scroll should behave like a **film edit controlled by the user**.

Never rely on:

- basic fade-in
- slide-up cards
- generic opacity transitions
- repetitive scale-from-0.9 effects
- random rotation
- default Framer Motion presets

Every reveal should be designed around the vehicle.

## 6.1 Scroll is the timeline

Down-scroll = move forward through the edit.

Up-scroll = reverse naturally.

Interactions must be reversible wherever practical.

Example:

- scroll down → Senna doors open
- scroll up → Senna doors close

The reverse motion must be just as clean as the forward motion.

## 6.2 The site should feel scrubbed, not triggered

Critical sequences should be tied directly to scroll progress rather than firing once at arbitrary thresholds.

Prefer scrubbed animation for:

- car rotation
- camera push / pull
- door motion
- component separation
- image-mask reveals
- engine reveals
- mechanical exploded views
- title choreography

---

# 7. SILKY-SMOOTH SCROLL — ZERO JITTER REQUIREMENT

This is critical.

The site must feel extremely stable.

No:

- image shaking
- snapping during sticky transitions
- layout shift
- scroll fighting
- sudden scale jumps
- Safari jitter
- pinning artifacts
- resize jumps
- low-FPS wheel input

## 7.1 Recommended motion stack

Preferred stack:

- **Next.js**
- **React + TypeScript**
- **GSAP**
- **GSAP ScrollTrigger**
- **Lenis** for smooth scrolling
- **Three.js / React Three Fiber only where true 3D adds value**
- WebGL shader layer for advanced image treatment

## 7.2 GSAP + Lenis integration

Synchronize Lenis with GSAP's ticker correctly.

Do not run competing requestAnimationFrame loops that drift apart.

ScrollTrigger refresh must happen after critical image dimensions and pinned sections are known.

## 7.3 Avoid layout-driven animation when transform-driven animation works

Favor:

- `transform`
- `opacity` only as a minor supporting property
- clip / mask systems
- shader uniforms

Avoid continuous animation of:

- width
- height
- top
- left
- expensive layout properties

## 7.4 Image stabilization

For all hero images:

- preload critical assets
- reserve exact aspect-ratio space
- avoid late dimension changes
- use `will-change` selectively
- use GPU-friendly transforms
- never animate an image whose intrinsic size is still unresolved

## 7.5 Refresh behavior

Support:

- resize
- orientation change
- route hydration
- browser zoom

without destabilizing pinned scenes.

The first 5–10 seconds of interaction must establish the visual standard immediately.

## 9.1 Opening concept

Start extremely minimal.

Possible visual:

- almost full black
- a tiny reflective automotive surface
- a single headlight line
- a close-up carbon weave
- a barely visible body panel

## 9.2 Example sequence

15–40%:

- zoom / dolly backward

Minimal.

- “I craft digital experiences”
- “Passionate developer building the future”

## 10.2 Signature interaction: Senna doors

Experience should appear as part of the automotive composition.

Examples:

- slim technical type aligned with body contour

## 10.5 Suggested copy density

Per experience item:

## 10.6 Micro-interactions

Potential:

# 11. PROJECTS SECTION — FORMULA 1

F1 represents engineering, simulation, systems, precision, performance, iteration.

This section should feel faster and more technical than the Senna section.

## 11.1 Visual grammar inspired by samples

Useful sample pattern:

- steering wheel detail
- cockpit / halo detail
- helmet / driver crop
- side profile
- front-on car reveal

Use the pattern, not the exact footage.

## 11.2 Section entry transition

Transition out of Senna through a shared mechanical form.

Examples:

### Option A: Wheel match-cut
Senna wheel fills frame → rotation accelerates → tread / rim transforms into F1 tyre → pull out into F1 car.

### Option B: Carbon match-cut
Senna carbon panel → extreme macro carbon weave → shader warps weave → resolves into F1 monocoque surface.

### Option C: Exhaust / heat transition
Rear Senna heat shimmer → visual distortion overtakes frame → distortion resolves into F1 engine / rear body section.

The transition must feel cinematic, not like a page section change.

## 11.3 Projects as F1 components

Projects can map to specific parts of the car.

Example:

- world-model / SportsNext → telemetry / steering wheel
- APEX → suspension / chassis / simulation layer
- UniMarket → system architecture / central control stack
- AfterFrame → optics / visual interface / cockpit information layer
- CC3K / engineering coursework → underlying mechanical systems

The mapping should be meaningful where possible.

## 11.4 Scroll-driven exploded detail

A strong project sequence:

- show complete F1 car
- scroll pushes camera toward one component
- component fills frame
- technical project content emerges from the geometry
- scroll continues and the component transitions into the next detail

This can create a pseudo-exploded technical journey without requiring an entire 3D paddock.

## 11.5 Tyre interaction

When a tyre is the focal object:

- pointer hover introduces subtle highlight / cursor response
- click or press initiates a short controlled spin
- spin should have believable acceleration / deceleration
- optional muted tyre scrub / hub mechanical sound

Do not spin forever.

## 11.6 Engine interaction

When engine / power-unit imagery is shown:

- press / hold may create a short engine ignition / rev response
- visual vibration should be almost imperceptible
- light / heat response can increase
- never shake the whole viewport

The image itself must remain visually stable.

## 11.7 Project text motion

Project titles should reveal through custom mechanical choreography.

Examples:

- letters exposed by a moving wheel mask
- title follows body-line reveal
- tiny metadata ticks into place like a telemetry readout
- stack labels lock into a technical grid after a camera move

Do not just `opacity: 0 → 1`.

# 12. ABOUT SECTION — NISSAN SKYLINE GT-R R34

## 12.2 Signature interaction: hood X-ray reveal

The Skyline initially appears with the hood **fully closed**.

As the cursor moves over the hood, a clean moving reveal allows the user to see the RB26 engine beneath it.

This should feel like:

- a high-end diagnostic scan
- technical X-ray vision
- a subtle material reveal

Not a gimmicky Photoshop wipe.

## 12.3 Reveal behavior

Cursor position defines the center of the reveal.

Possible effect stack:

1. soft elliptical mask
2. slight displacement at edge
3. subtle scan texture
4. mild RGB split only at the boundary
5. engine image / render perfectly registered under hood
6. very slight internal parallax
7. fine technical line overlay if useful

The hood surface should still feel present around the reveal.

## 12.4 Accuracy requirement

The engine underneath must align plausibly with the Skyline engine bay.

Do not place a random engine under the hood.

If using RB26 imagery / rendering, verify layout carefully.

## 12.5 Mouse trail behavior

The cursor should not leave a cheap glowing trail.

Instead, it can leave a short-lived **diagnostic residual**:

- faint scan line
- temporary engine reveal persistence
- short decay
- subtle noise pattern

The effect should disappear quickly and feel precise.

## 12.6 About copy

Use extremely little copy.

Potential content categories:

- Waterloo CS
- motorsport / F1
- football
- VFX / filmmaking
- systems / ML

`I BUILD THINGS I WANT TO EXIST.`

Only use statements that genuinely fit the person; avoid manufactured slogans.

## 15.2 Preferred text motion

- text revealed by body-panel mask
- letters emerge from behind a wheel
- title tracks with camera motion then locks in place
- baseline extends like a technical measurement line
- small metadata arrives with instrument-like timing

Typography should feel:

- modern
- editorial
- mechanical
- restrained
- premium

Avoid “AI startup” type treatment.

Avoid unnecessary gradient text.

# 19. PERFORMANCE TARGETS

The experience is visually ambitious, but performance is part of visual quality.

A cinematic page that stutters is a failed cinematic page.

## 19.1 Targets

Aim for:

- 60 FPS on capable modern desktop hardware
- graceful reduction on weaker devices
- no blocking hero asset swaps during scroll
- no late image decode flashes
- minimal cumulative layout shift

## 19.2 Progressive quality

Use device capability tiers.

High tier:

- full WebGL displacement
- high-res hero assets
- richer depth
- full component interactions

Medium tier:

- reduced shader detail
- reduced texture resolution
- fewer simultaneous layers

Low/mobile tier:

- pre-rendered sequences
- simpler masks
- fewer live 3D elements
- preserve core choreography

# 21. IMAGE-SEQUENCE ANIMATION

For certain hero moments, high-quality image sequences may outperform live 3D.

Good uses:

- Senna door opening
- controlled camera orbit
- F1 component rotation
- Skyline reveal

## 21.1 Rules

- render at stable framing
- match exposure frame-to-frame
- preload intelligently
- scrub to exact scroll progress
- interpolate or use enough frames to avoid stepping
- avoid 100+ MB uncompressed disasters

Use AVIF/WebP sequence strategies or video where appropriate.

# 22. WEBGL / SHADER USE

WebGL should be used when it creates something CSS cannot do convincingly.

Good applications:

- hood X-ray reveal
- depth displacement
- reflection movement
- heat shimmer
- transition warps
- selective lens distortion

Bad applications:

- random noise because it looks “tech”
- constant RGB glitch
- shader effects that reduce readability

# 38. VISUAL QA CHECKLIST

For every car shot ask:

- Is the car the first thing I look at?
- Does it look physically plausible?
- Are the reflections helping the body shape?
- Is the background too busy?
- Does the crop feel intentional?
- Does the wheel look circular, not warped?
- Do badges / lights / seams look correct?
- Does the image hold up on a 4K display?
- Does it still look premium when paused?

If not, revise.

# 39. MOTION QA CHECKLIST

For every transition ask:

- Is there a visual reason for this transition?
- Does the next section emerge from the previous one?
- Is the motion reversible where needed?
- Does it feel like camera movement instead of DOM movement?
- Does it preserve image stability?
- Is there any generic fade that could be replaced by a vehicle-led reveal?
